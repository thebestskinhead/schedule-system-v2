## 值班次数口径（运行时聚合）

- 取值 = `SELECT user_id, COUNT(*) FROM duty_records WHERE user_id IN (...) AND status <> 'cancelled' GROUP BY user_id`，即「有效班次数」；`cancelled` 不计入，`pending`/`confirmed`/`completed` 计入。
- 造数据实测：排班确认后聚合结果与预期逐人一致；单格增删、状态置 cancelled 后聚合随之变化，无冗余副本需要维护。

## 权限前置条件（关键）

在**真实 3306、`log_bin=ON`、`log_bin_trust_function_creators=0`、仅持库级权限的 `schedule_test` 账号**下复验：

- 存量迁移（011/012/013）：**rc=0**；
- 全新安装（`init_db.sql`）：**rc=0**；
- 对象结果：触发器 0 / 存储过程 9 / 事件 1。

结论：**初始化与迁移不再依赖 `SUPER`、`SET_USER_ID` 或 `log_bin_trust_function_creators` 等服务器级权限**，任何 MySQL 8 实例（含云上只给子权限的账号）均可直接完成。

## 文档冲突与未覆盖

- §2 曾称删 `users.joined_at`/`left_at`，实际两列不存在 → 不处理。
- 事件 `evt_cleanup_expired` 采用分批 `LIMIT 1000` 循环写法。

## 风险点

- 011 生产执行前确认 `duty_counters_backup_<日期>` 未同名存在（已 `IF NOT EXISTS` 兜底）；大表去重与加约束注意锁时长。
- 存储过程正文通过 `JSON_TABLE`、`SIGNAL SQLSTATE`、`DECLARE HANDLER` 实现，需 MySQL 8.0+；`encoding` 建议 `utf8mb4`。
